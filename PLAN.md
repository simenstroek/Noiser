# Noiser — reference and plan (draft 1, 2026-11-17)

Native Rust app for building tiling 3D noise in a node graph. It previews the result as an SDF raymarch, exports 2D/3D textures, and exports a portable math-function file that other tools (Blender first) can sample.

## 2. Proposed architecture

```
graph (serde model)  ──►  IR (flat SSA op list, versioned)  ──►  WGSL codegen ──► GPU: raymarch / slice / export compute
                                     │
                                     └──►  .noiser file (math-function export) ──► samplers: Blender add-on, later HLSL/GLSL/…
```

- **One evaluator: the GPU.** The graph compiles to one WGSL function `field(p: vec3f) -> f32` (plus `normal(p)`). The raymarcher, the 2D slice view and texture export all call it. Node parameters live in a uniform buffer, so dragging a slider doesn't recompile; only changes to graph topology rebuild the shader (WGSL compiles in milliseconds).
- **No separate CPU noise implementation.** Test vectors for samplers come from GPU readback. That saves writing every noise twice. *Trade-off: no headless CPU export. Add a CPU path only if needed.*
- **The IR is the file format.** A JSON list of ops (`{"id":3,"op":"perlin","in":{"pos":1},"params":{...}}`), with a `version` field and a written spec per op, including the exact hash function. Any sampler that implements the spec reproduces the result bit-for-bit (within float tolerance) and checks itself against bundled test vectors.
- **Tiling status** is computed per node by propagation. A node is non-tiling if it is inherently non-tiling, if its scale/lacunarity isn't an integer, or if any upstream input is non-tiling. Non-tiling nodes get an orange outline and a tooltip that says *why*.
- **SDF + displacement**: `d(p) = sdf_primitive(p) - amount * noise(p)`. Displacement breaks the SDF's Lipschitz bound, so the raymarcher scales its step size by `1/(1 + amount·|∇noise|max)`. A user-visible "step safety" slider is the cheap version of that.
- **Cloud mode**: treat `density = max(0, -d) * k` and do Beer–Lambert volume marching with one light, using the same field function.

### UI layout (egui_dock)
Node graph (centre) · 3D view (primitive picker, solid/cloud, displacement amount, orbit camera) · 2D slice view (axis X/Y/Z, slice slider, grayscale/heatmap, auto-normalize by min/max reduction) · properties panel for the selected node.

### Nodes (v1)
- **Noise**: Perlin, Simplex (psrdnoise), Worley (cellular, see below), White, Blue.
- **Value** (float or vec3), **Math** (add/sub/mul/div/min/max), **Position**, **Normal** (gradient of the input, flip option).
- **Outputs**: Density (SDF in the math export; 0–1 for 8/16-bit, signed for 32-bit), Normal (vec3).

### Noise notes (milestone 4)
- **Hash**: pcg3d on the wrapped integer cell, so every noise tiles by wrapping its lattice every `scale` cells. Octaves use `seed + octave`. (Briefly switched to Blender's Jenkins hash on 2026-11-17 so a stock Blender node could reproduce it, then reverted the same day: it cost 2–4.6× preview speed. See the hash-cost note below.)
- **Simplex** uses psrdnoise's BCC lattice (`uvw = M·x`, kernel `max(0.5 − r², 0)⁴`, gain 90). Its features are slightly finer than Perlin's at the same scale.
- **Worley** (one node; Voronoi and Voronoi Fractal were merged into it on 2026-11-17) searches 3×3×3 cells, fully jittered. Feature: F1 (default), F2, F2−F1, or Cell value (a flat random value per cell, the old Voronoi). The first three map to signed [-1, 1] using typical ranges (1, 1.4, 1). **Fractal** is a checkbox: off means one octave, on shows octaves, lacunarity and roughness. Old files migrate on load (`migrate_noise_kinds` in `graph.rs`): Voronoi becomes Cell value, Voronoi Fractal adds Fractal, and a Worley saved with octaves above 1 stays fractal.
- **Blue noise** is a lookup into precomputed void-and-cluster tables (4³, 8³, 16³, 32³) in `assets/bluenoise.bin`. It tiles only when the scale is a multiple of 4. The seed shifts the lookup by whole cells.
- **GPU tests** (`src/gpu_tests.rs`): seam check per axis, a 1e-4-step continuity check across the tile edge, and a signed-range check. `cargo test noise_contact_sheet -- --ignored` writes `target/noise_sheet.pgm` for a visual check. GPU tests take a shared lock in `gpu()` so they run one at a time: with about ten of them creating Vulkan devices in parallel, the suite intermittently hung (always inside GPU tests); serialized, 15 of 15 full runs finished.

### Performance notes (2026-11-17)
- **Measure** with the in-app overlay (GPU timestamps for the 3D pass and slice pass, plus CPU time for the UI), or headless with `cargo test --release bench_preview -- --ignored --nocapture` (1000×1000, median of 30 frames).
- **Overlay numbers depend on GPU clocks.** egui only redraws on input, so the GPU idles and drops its clocks. The first frames after a pause can read 3–5× slower than the steady-state numbers in the benchmark.
- **Noise inner loops:** avoid integer `%` per neighbour (wrap the base cell once, then `wrap_near`). Avoid loops over local arrays (they spill out of registers; write corners out by hand). Hash only what's needed. These changes alone took the 3D view from 24 to 10 ms and the slice from 1.2 to 0.24 ms.
- **Raymarch:** noise runs only in the displacement shell (margin 0.02). Overshoot is fixed with 4 false-position steps rather than 12 bisection steps. The default step safety is 0.9, since overshoot is cheap to correct.
- **Shader compile time matters as much as run time.** On this machine (Vulkan, NVIDIA) the driver compiles pipelines synchronously, and every topology change makes a new shader. Uncached, SimpleTestGraph took 4.5 s, which froze the UI and looked like a lost edit. Now pipelines build on a worker thread, and the old pipeline keeps drawing with its own parameters until the new one is ready ("Compiling shader…"). Codegen emits one fBm function per noise kind used (`noise_fbm.wgsl` template) instead of a 7-way runtime switch, and tetrahedral sampling loops over one call site. Together that brought uncached compiles to 0.84 s (SimpleTestGraph) and 1.25 s (with one more noise). Measure with `NOISER_BENCH_BUST=1` on `bench_preview`.
- **Hash cost (measured 2026-11-17, RTX 4070 SUPER, A/B on the same machine, `NOISER_BENCH_BUST=1`)**: Blender's Jenkins hash (3 calls of about 40 integer ops per lattice random) against pcg3d: solid 3D 8.2 → 17 ms (2.1×), slice 0.23 → 1.0 ms (4.6×), cloud 65 → 154 ms (2.4×), cold pipeline build 0.83 → 2.1 s (2.5×). Decision: keep pcg3d. Blender 5.3's Geometry Nodes have Integer Math and Bit Math nodes, and pcg3d rebuilt from them matches exactly, so Blender loses nothing there (shader trees have no Bit Math, so they use the texture bake).
- **Shader library size costs compile time (measured 2026-11-17).** Adding the mesh mask, the pattern kernels and the general Worley to the one always-included `noise.wgsl` took pipeline builds from 0.82 s to 1.67 s even for graphs that used none of them: the driver compiles unused functions too. Fix: they are separate libraries emitted only when needed (`mesh_mask.wgsl` when a mesh with mask terms is shown or exported, `patterns.wgsl` when the graph has a Pattern node, `worley_general.wgsl` when a Worley node uses a non-default metric, jitter or Cell edges), back to 0.84 s. The default Worley also keeps its original loop (`cells_classic`), since the general one (metric and jitter per feature point) cost 5 to 10% of frame time on a Worley-heavy graph. Tests check that the general loop agrees with the classic one bit for bit at the defaults, and that the default Worley equals a copy of the pre-variants implementation. Rule: new WGSL goes in a gated library unless every graph needs it, and benchmark `bench_preview` after adding any.
- **Cloud mode costs about 10× solid** (69 ms at 1 MP with SimpleTestGraph): 128 steps × (1 + 5 shadow taps) of full graph calls inside the shape. The structural fix is the baked 3D texture (milestone 5 groundwork).

### Per-node cache (decided 2026-11-17, milestone 5)
- **Resolution-independent detail is a core feature**, so the graph stays procedural by default. Each node gets a **cache toggle, off by default**. When it's on, the upstream subgraph is baked into one tile of a 3D texture (wrap sampling, exact because it tiles), and downstream nodes read the texture.
- **Export ignores every cache** and evaluates the full graph at the output resolution.
- **Budget:** 1024³ f16 is 2 GiB per node, and 20 of them would be 40 GiB, so caches must be chosen by hand and sized per node. The default resolution comes from the node's finest feature: about 4 samples per finest cell, where cells = scale × lacunarity^(octaves−1). Scale 4 with 4 octaves gives 128³ (4 MiB at f16). The user can override it, and a VRAM meter shows the total.
- **Sampling:** cubic (B-spline, built from 8 linear fetches) rather than plain linear, so normals and Normal nodes downstream of a cache aren't faceted.
- Graphs that don't tile bake over the base shape's bounds instead.
- **Built (`src/cache.rs`)**:
  - Noise and Math nodes that output a float and tile can be cached; the toggle is a button in the node header next to the eye (Material Symbols sync-saved-locally, outline when off), and its tooltip says why a node can't be cached. Resolution sits under the node's properties.
  - Resolution is Auto (≈4 texels per finest noise cell, power of two, 16–512) or a fixed 32–1024; the panel shows MB for this cache and for all.
  - Textures are R32Float with Repeat wrapping, sampled with a cubic B-spline built from 8 trilinear fetches. Needs the FLOAT32_FILTERABLE feature; without it caches are sampled unfiltered (blocky).
  - At most 8 caches at once (shader slots).
  - Bakes run as compute dispatches, and a new bake pipeline compiles on a worker thread, keyed by upstream WGSL. A parameter change only re-dispatches the bake.
  - A bake evaluates the node's full upstream graph, so caches don't nest. Nodes that only feed caches (every path to an output or the previewed node passes through a cache) get a green outline, since the preview no longer evaluates them (`Graph::cache_covered`). The `cache` field is saved in the graph file.
  - Export never uses caches.

### Crash recovery (`src/backup.rs`)
- Each running instance has a session folder in `%APPDATA%\Noiser\data\sessions\`. It holds a `lock` file the instance keeps exclusively locked, plus rolling backups (the last 10, at most one per second).
- Backups only run while the graph differs from what was last opened, saved or created.
- **Clean exit** deletes the folder. After a **crash** the OS releases the lock, so on the next start any folder whose lock can be taken is a crashed session. Folders whose lock is still held belong to other running instances. The newest crashed backup is offered in a Restore/Discard prompt.
- No "unsaved changes?" prompt on exit yet.

### UI conventions
- **Every value input has a reset-to-default button** in front of it (the `row`/`reset` helpers in `main.rs`).
- **Interface icons come from Material Symbols** via Iconify (https://icon-sets.iconify.design/material-symbols/). Save each icon as an SVG in `assets/icons/` with `currentColor` replaced by white so egui can tint it. License: `assets/icons/LICENSE.txt`.
- **Warnings go below the controls** in the details panel ("Does not tile: …"). When one appeared above the sliders it shifted the slider out from under the cursor mid-drag and ended the drag.
- **The node editor is custom** (`src/editor.rs`), not egui-snarl: no node-graph crate supports egui 0.37, and box select is needed for subgraphs (milestone 8).

### Design rules that keep milestone 7 cheap
- **The base shape is a swappable slot, outside the graph.** The shader calls `base_sdf(p)`, which is a primitive today and a sampled 3D texture of the mesh SDF later. The graph only defines the noise. The math-function export stays noise-only, and each sampler applies it to its own geometry.
- **Noise lives in object space, with its own tile size.** The base shape's transform also moves the noise, so it sticks to the object. A separate **tile size** scales the tiling space relative to the object/mesh: `noise(p_object / tile_size)`. One tile is still 1 unit of *noise* space, so exports are unaffected.
- **Subgraphs (milestone 8) are inlined at compile time.** Ports are addressed as (node, input index), and codegen compiles whatever graph it's given. A subgraph node then only needs a flatten pass before codegen, so the shader and the `.noiser` format don't change.
- **One "sample the field on a grid" path.** The z-slab GPU compute that texture export uses also feeds the VDB writer and the mesher. The VDB writer is shared by texture export and mesh export.

- **Bricks** (done; the first node of the planned pattern family, `NodeKind::Pattern(PatternParams)` with `PatternKind::Bricks` as the only kind so far): a staggered brick wall. Counts per tile along a row and along the rows (default 8 × 16, bricks twice as wide as tall), 2D mode extruded along a chosen axis (default Z) or 3D with layers, and **row offset steps** (1 stacks bricks in a grid, 2 is a running bond and the default, 3 shifts by thirds; the number of rows must be a multiple of the steps to tile). Three outputs: **Distance** (default, as you described: distance to the centre of the brick you are in, scaled so the centre is -1 and the corners +1; with steps = 1 it is exactly the Grid's centre distance), **Shape** (-1 on the brick face, +1 in the mortar; mortar gap and edge softness) and **Cell value** (a flat random value per brick; bricks across the tile edge hash the same id). The `.noiser` format writes `metric`, `jitter` and feature `edges` only when they are not the defaults. Not built: even-cells Voronoi (a relaxed point set), (the pattern plan is otherwise finished). That finishes `docs/pattern-nodes-plan.md` except those.
- **Absolute and Ridge** (done): the unary Math operators.

## 3a. Mesh pipeline sketch (milestone 7)
1. **Import**: OBJ (`tobj`) and glTF (`gltf`). FBX is out of scope.
2. **Mesh → SDF**: a narrow-band grid, with resolution and band width set in the app. Distance comes from a BVH closest-point query. The sign comes from the **generalized winding number**, which tolerates small holes and is more forgiving than "must be closed". Candidate crate: `mesh_to_sdf` (check sign quality first). It can move to a GPU compute shader if it's too slow.
3. **Band width must cover the displacement.** Values outside the band are clamped, so the noise can't push the surface further than band − margin. The UI sets the minimum band from the displacement amount, or warns.
4. **Apply noise**: `d = base_sdf(p) − amount·noise(p)`, sampled through the shared grid path. The preview uses a downsampled dense 3D texture (for example 256³). Export works brick by brick, over the band only.
5. **Export**: VDB (the shared writer), or a mesh via **Dual Contouring** (decided 2026-11-17). It places one vertex per cell by minimizing the QEF from the field's gradients, which keeps sharp features. Clamp each vertex to its cell to avoid spikes. Output as PLY/OBJ/glTF.
6. **Memory**: dense grids above about 1024³ get too big, so the high-res path uses sparse bricks (only cells inside the band). The resolution warning from texture export applies here too.

### Mesh pipeline (built 2026-11-17, milestone 7)
How it works (files: `mesh.rs`, `meshsdf.rs`, `meshapp.rs`, `meshexport.rs`, `surface.rs`):
1. **Import** (OBJ via `tobj`): objects are merged, faces triangulated, vertices at the same position welded, and the mesh normalized (centred, bounding sphere radius 1, like the unit primitives; the export undoes it). `noiser.exe --mesh file.obj` loads one at startup.
2. **Mesh to distance grid** (CPU, rayon): a BVH finds the closest triangle, and the sign comes from the **generalized winding number** (Barill et al. fast far-field sum, `|w| > 0.5` is inside), not a closest-feature normal test, so meshes made of overlapping closed parts, inside-out parts and meshes with small holes get a sensible inside. Baked at 128 voxels along the longest side by default plus a padding (default 0.5 of the mesh radius) that must cover how far the noise can push the surface; the panel warns when it doesn't. 63k triangles take about 5 s, 240 take under a second.
3. **Preview**: the grid is an R32Float 3D texture (bind group 2), read with `textureLoad` and manual trilinear (no filtering feature needed), and beyond the grid the distance keeps growing. "Mesh" is shape 7 in the shape list; `base_sdf` is `mesh_sdf_at(...)`, so displacement, tile size, shape size, seed and the cache all work as for the primitives.
4. **Export**: `field = mesh_distance - amount * graph_density(p / tile_size)`, the preview's own formula, evaluated on the GPU in slabs of 8 layers (`MeshEvaluator`), streamed into **surface nets** (`surface_nets`, never holds the whole grid). Vertex normals are the field's gradient. Small floating parts are dropped by **surface area relative to the largest part** (default 1%), so several large parts all stay. OBJ or binary PLY. The grid resolution is the "samples along the longest side" setting: 240 triangles became 700k at 200 × 263 × 204 samples in 4.5 s.
5. **Checked**: unit tests on the BVH, the winding number against the exact sum, closed meshes and outward orientation; GPU tests that a sphere exports as the sphere, every exported vertex lies on the zero level of the displaced field, shape size and normalization are undone in the written file, and seeds change and repeat. `tools/render_obj.py` renders an OBJ with Blender's Workbench for a look; `NOISER_TEST_MESH=file.obj cargo test export_a_real_mesh -- --ignored --nocapture` runs the pipeline headless on a real file.

6. **Batch** (`FileJob`, `SeedMode`, `batch_window`): one graph over many OBJ files on a worker thread. Each file goes load, normalize, distance grid, GPU evaluator, surface nets, write, with the same displacement, tile size, shape size and export settings as the single export. Seeds: same, global + index, or a splitmix64 hash of (global, index) kept below 2^24 so it is exact as a float; non-same seeds go in the file name. Normalization makes the noise the same size relative to every mesh (a test checks a copy scaled 3× displaces identically). A failing file (including a panic, via `catch_unwind`) is reported and the rest go on; existing files get a `_2` suffix instead of being overwritten. `--batch-out DIR --batch-file F` starts one from the command line. Headless batch is built (`headless.rs`; `noiser-batch.cmd` waits for it and returns the exit code). Not built: per-mesh settings (only the seed and the amount vary).

Differences from the sketch in 3a, and known limits:
- **Surface nets instead of Dual Contouring.** Simpler and robust; it rounds sharp edges by about a voxel and, where a cell's corner signs are ambiguous, leaves a few non-manifold edges (7 in 110k on a noisy sphere, never holes). A DC mesher (QEF per cell, sharp features) is the upgrade if sharp edges matter.
- **Overlapping parts keep their internal faces in the distance**, so near an internal face the distance is small even though both sides are inside. With large displacement that can open thin internal cavities (separate inner surfaces, usually culled as small parts). Cleaning the mesh (boolean union or remesh) first avoids it.
- No UVs, vertex colors or materials survive: the output is a new surface. The mask terms (position gradient, normal, occlusion, thickness, curvature) below are not built yet.

### Displacement control and island culling (requested 2026-11-17, for milestone 7; the mask terms are built)
**Built (`meshmask.rs`, `mesh_mask()` in `noise.wgsl`, the Displacement mask section of the Mesh panel):** up to six terms, each a Constant, a Position ramp along an axis (either direction), a Normal direction (dot product with an axis), Occlusion (IQ's distance-field AO), Thickness (march inward along the normal until the field turns positive) or Curvature (mean curvature from a second difference of the distance grid). Each is remapped from an input range to 0..1 and clamped, can be inverted, and is multiplied by a weight (-2 to 2); the mask is their sum, and with no terms it is 1. Terms are evaluated at the nearest surface point (`p - n * d`), so the mask is a property of the surface, constant along the normal. They use only the mesh's distance field, never the displaced one. The preview and the export share the one WGSL function, and the displacement reach used for the shell skip, the export region and the padding warning includes the mask's range. The export also skips the noise for samples farther from the surface than the reach (they cannot cross zero), which is what keeps large exports fast. A test reads each term back from the exported surface of a unit sphere. Not built: vertex color or painted masks (the plan below still holds: interpolate an attribute at the closest triangle while baking the grid). The mask visualization (Show mask on the mesh) is built.

`d(p) = base_sdf(p) − amount · mask(p) · noise(p)`, where `mask` is a **weighted sum of terms**, each with its own weight and remap/clamp:
- **Position gradient** along X/Y/Z (a ramp over the object's bounds).
- **Normal**: dot of the surface normal with a chosen axis, remapped and clamped. The normal is the gradient of the base SDF, so it comes free from the grid.
- **Occlusion**: SDF-based AO (a few samples along the normal, as in IQ's AO).
- **Thickness**: march inward along the negative normal until the SDF turns positive again.
- **Curvature**: mean curvature, the divergence of the normalized SDF gradient, by finite differences on the grid (convex and concave get opposite signs).

**Every term is derived from the base SDF only, never from the displaced field**, so the mask can't feed back on itself. That means occlusion and thickness (the expensive ones) bake **once per mesh** into mask channels at SDF resolution, and only the weights, remaps and noise stay live. The preview samples the channels, and export reads them through the same grid path.

**Vertex color / painted masks (my advice: yes, as scalar channels).** It survives the SDF conversion the same way distance does: the mesh-to-SDF pass already finds the closest triangle per voxel, so interpolating a vertex attribute (barycentric) at that closest point gives a painted value per voxel, stored as one more mask channel. Cheap, and the band is exactly where displacement acts. Limits: color edges blur to voxel resolution, and where two surfaces sit within a voxel (thin walls) the nearer triangle wins. Treat it as a scalar mask (pick one color channel or a named attribute) rather than full RGB. Import needs a format that carries it: glTF `COLOR_0` or PLY, not plain OBJ.

**Culling tiny floating parts on export, keeping multi-part meshes.** Label connected components of the inside region on the grid (union-find over bricks) before meshing, then drop components below a size threshold (volume, as a fraction of the largest component or an absolute size in object units). A multi-part mesh survives because its real parts are large. An option, **keep every component that contains part of the original mesh**, protects deliberately small parts: displacement-made floaters appear either outside the base surface (outward bumps that detach) or as fragments cut from the body, so "contains base mesh" separates them from intentional small parts. The VDB export clears the culled voxels, and mesh export never meshes them.

## 4. Samplers: how other software evaluates a `.noiser` file

**Strategy (decided 2026-11-17).** Matching every host's built-in noise nodes can't last: we plan to export to Houdini and others too, and each host's nodes differ. So the file stays host-neutral and each host gets a purpose-fit **sampler plugin** that reads our own graph format and implements the ops natively, with **texture bake as the fallback** where a host or an op can't do it. Baking is universal but needs very high resolution to keep the detail, so it's the second choice, not the first.

- **Spec**: `docs/noiser-format.md` (JSON op list, one hash, written definitions, test vectors). The hash is pcg3d, about 10 lines of u32 code in the spec, so any host with integer ops can implement it directly.
- **Conformance**: each file embeds test vectors (the GPU result on a 6³ grid). A sampler passes when it matches within 1e-4. Noiser can write them (`File > Export Math Function`), and `cargo test noiser_files_for_blender` writes sample files to `target/blender/`.
- **Blender** (`blender/noiser/`, an extension for 5.2+; checked on 5.3, and the Bit Math node it needs hasn't been checked in 5.2): File > Import > Noiser Function builds a Geometry Nodes group from stock nodes (Integer Math and Bit Math for pcg3d), with a Position input and a Density output. Checked headless: `blender/check_file.py` (five Perlin graphs, 344 test points each, max error about 1e-6), `blender/check_hash.py` (hash alone, 201 cells, exact) and `blender/check_addon.py` (the real import operator). Perlin is a reusable group of about 450 nodes but evaluates live at any resolution. **No shader group**: shader node trees have no Bit Math node, so shaders use the texture bake.
- **Houdini** (next): a VEX sampler is the natural fit (VEX has the u32 ops the hash needs). Same test vectors.
- **Fallback**: Noiser's VDB and slice-grid exports (milestone 5).
- **Not yet in the format/add-on**: Simplex, Worley, White, Blue
- **Not worth doing**: a Python sampler that writes attributes (an operator, not live).

### Compile time and shader shape (measured 2026-11-17 night, RTX 4070 SUPER, `NOISER_BENCH_BUST=1 cargo test bench_preview -- --ignored --nocapture`)
